## 今日结论

1. **AI-for-AI 的短板不是不会执行，而是不会在实验中推翻自己的高层策略。** 新实证显示，Post-training Agent 一旦开局选定路线，后续预算大多耗在局部调整；经验、人工提示和更多推理算力都未根治这个问题。
2. **“选哪个 Skill”需要独立的信用分配。** SkillGate 指出，长轨迹的终局奖励几乎无法训练少量的技能选择 token；分离选择与执行的 advantage 后，9B 模型成功率由 40.8% 升至 53.2%。
3. **Computer-use Agent 的接口设计可造成超过 30 个百分点差距。** ComponentBench 表明，同一模型、同一 harness，仅把 accessibility tree 换成坐标像素控制，GPT-5 mini 即由 83.1% 降至 48.9%。采购和评测不能只报模型名。
4. **代码 Agent 的能力边界是锯齿状的。** 语义不变的控制流改写、死代码和变量改名仍可造成最高 6.7 个百分点下降，而且模型的鲁棒性排名会随 scaffold 改变。

## 研究前沿

### 1. Post-training Agent 缺少“策略级反思”

**论文 / 日期：** [What is Missing from AI Post-Training AI: An Empirical Analysis](https://arxiv.org/abs/2608.19072)，2026-08-19 提交；作者包括 Joy Jia Yin Lim、Xin Huang、Hao Peng、马少松、林衍凯等。

**问题与方法。** 论文把自主后训练拆成两层：执行层是在既定训练方案里写代码、跑实验和调参；策略层是在证据积累后重新判断“方案本身是否错了”。作者分析公开的后训练轨迹，并分别加入经验 scaffold、人工指导和额外 inference compute，检验三种常见解释。

**关键结果（作者主张）。** 经验 scaffold 将 GSM8K 提升 **12.6 点**、HumanEval 提升 **40.8 点**，但策略仍保持开局锁定；人工指导能改变初始路线，训练启动后 Agent 又回到局部微调循环；更多推理计算只对较容易任务有效，在最难任务上几乎没有收益。

**增量。** 它修正了“Agent 能自动跑完后训练＝Agent 会做研究”的混淆。真正的研究能力应包含主动提出反证、设置停止条件和跨策略比较，而非把同一路线执行得更久。

**局限 / 工程价值。** 结论依赖所分析的公开轨迹和任务，不能直接外推到所有科研 Agent。工程上应把策略假设、反证指标与触发重规划的规则做成显式状态，而不是只增加 token 预算。arXiv 页面未列出明确代码仓库，本次深读以摘要和论文元数据为主。

### 2. SkillGate：修复长程 Agent 的技能选择信用饥饿

**论文 / 日期：** [SkillGate: Training In-Policy Skill Selection in Long-Horizon Agents](https://arxiv.org/abs/2608.18852)，2026-08-19 提交；上海交大等团队。

**问题与机制。** Agent 从数千个 Skill 中按需读取说明已成为常见架构，但选择动作往往只有几个 token。若把整条轨迹的终局 advantage 广播给所有 token，技能选择获得的梯度占比极小；更糟的是，正确选择之后若执行失败，选择本身也会被负向更新。作者称其为 **selector credit starvation**。

SkillGate 将 token 支持集拆成两个互斥通道：终局 outcome credit 只训练执行 token；局部 action advantage 只训练命名 Skill 的 token，并在单次读取命中正确技能时给予正向信号。

**关键结果（作者主张）。** 在 5 个 Agent benchmark、16 个候选 Skill 的设置下，9B 策略成功率由 **40.8% 提升到 53.2%**；相比相同预算的纯终局奖励，接触误导候选的次数减少约三分之二，同时读取更少技能。

**增量与边界。** 贡献是把“检索 Skill”视为轨迹内策略动作，而非外置 RAG。当前正信号依赖能判断“正确 Skill”的监督，面对多个同样有效的 Skill、组合调用或没有标准答案的真实任务时，局部 advantage 如何构造仍是难点。

**复现 / 工程价值。** 高。arXiv 条目显示作者提供代码与 Hugging Face 模型入口，但本次抓取未解析出仓库的完整目标地址；接入前需再核验许可证、训练配置和评测脚本。

### 3. ComponentBench：模型之外，观察与动作空间决定 Computer-use 上限

**论文 / 日期：** [ComponentBench: Diagnosing Component-Level Failures in Computer-Use Agents](https://arxiv.org/abs/2608.18307)，2026-08-18 提交，已被 COLM 2026 接收；[项目页](https://componentbench.com/)。

**问题与机制。** 现有评测一端是长流程任务，失败后难定位；另一端是过于原子的 GUI grounding。ComponentBench 建立 97 类与前端库无关的 UI 组件本体，生成 **2,910 个**可程序验证任务，并提供清洗后的人类轨迹，同时测成功率和交互效率。

**关键结果（作者主张）。** 团队测试 7 个模型和 4 种观察 / 动作空间。同一 harness 内，GPT-5 mini 使用 accessibility-tree 观察时成功率 **83.1%**，换成纯坐标 Pixel 控制后降至 **48.9%**；即使最快配置，耗时也是对应人类轨迹的 **3.7 倍**。

**增量。** 它补上了“组件级”诊断层，可回答 Agent 究竟败在下拉框、空间拖拽、状态感知还是长程规划。结果也说明，模型榜单若不固定 action space，横向排名缺乏可比性。

**局限 / 复现价值。** 程序生成组件比真实网站更干净，尚不能覆盖广告、延迟、弹窗和登录态等生产噪声。项目页、代码和数据均在 arXiv 条目中列出，适合作为浏览器 Agent 的回归测试集。

### 4. 语义等价改写仍会扰动代码 Agent

**论文 / 日期：** [A Jagged Frontier: Evaluating Robustness of Code Agents to Semantics-Preserving Transformations](https://arxiv.org/abs/2608.18389)，2026-08-18 提交；Colorado State、Microsoft、UIUC、CMU 团队。

**问题与方法。** 作者对 SWE-bench Verified / Pro 实例随机施加语义保持变换，包括控制流改写、死代码注入和标识符重命名；在 mini-SWE-agent 与 OpenCode 两种 scaffold 上搭配 4 个模型，并对原始与扰动版本重复运行，用配对 resolve rate 分离改写影响与 Agent 自身随机性。

**关键结果（作者主张）。** 最受影响配置平均解决率下降 **6.7 个百分点**；16 个“模型×scaffold×数据集”配置中有 6 个出现统计显著退化。鲁棒性没有统一排名：Qwen 在 mini-SWE-agent + SWE-bench Verified 中较稳，却在 OpenCode 下最脆弱；较简单的 mini-SWE-agent 整体更稳。

**增量与边界。** 论文比单次 pass rate 更接近软件可靠性测试，并揭示模型与 scaffold 的交互效应。变换集合仍有限，且“语义等价”不代表对人类可读性和项目惯例完全等价。arXiv 条目未列明确代码链接，本次以摘要级结果核验。

1. **策略级重规划机制。** 看后续 AI-for-AI 系统能否在无人工提示下，根据反证主动终止原方案并切换训练策略。
