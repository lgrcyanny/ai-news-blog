## 今日结论

1. **“递归自我改进”目前离能改造学习算法还很远。** AI4AI-Bench 中最强系统平均只达到 0.250 分；多数提交根本不改变学习机制，更多推理主要提升“愿不愿意尝试改算法”。
2. **通用工具使用应前移到 mid-training。** MidTool 把真实 API、MCP Skill 与文档工作流合成为训练语料，在 BFCL、tau2-Bench、MCP Universe 上同时改善 SFT 与 RL 后训练的效果；这比只在最后做 function-calling 对齐更像能力塑形。
3. **Skill 选择正从启发式检索变成优化问题。** 一篇理论+实证工作把有限 context 下的 Skill 集合建模为“收益减 token 代价”的子模优化；在其受控 BigCodeBench 变体上，成功率 0.73、且 token 更少，但还需跨真实 Skill 库验证。
4. **本周第二篇审计工作再度警告：自训练的“逐题能力跃迁”很容易是测量幻觉。** 没有与实验管线完全匹配的冻结对照、重复采样与多重检验，不应把 gain/loss 账本当作能力增长。

## 研究前沿

### 1. AI4AI-Bench：先量出 Agent 是否真的会改训练算法

**论文 / 日期：** [AI4AI-Bench: Benchmarking LLM Agents in Algorithmic Design for Recursive Self-Improvement](https://arxiv.org/abs/2608.20318)，2026-08-20 提交。

**问题与机制。** 许多“自改进”评测允许 Agent 追加数据或调超参，不能区分“更会执行一场训练”和“改变模型如何学习”。该 benchmark 冻结 10 个、覆盖 10 种训练算法族的研究仓库：Agent 在一张 B300 上有 4 小时改写训练算法；系统随后从头运行至多 12 小时，由对 Agent 隐藏的固定评测器与原算法对比。不同任务指标被映射到统一尺度：0 是无信息模型、0.1 是仓库原算法、1.0 是任务最优。

**关键结果（作者主张）。** 6 个系统、29 个配置的平均分仅 **0.166**，最强为 **0.250**；真正修改学习机制的少数提交平均 **0.226**，未修改者为 **0.126**。提高 reasoning effort 后，尝试算法修改的比例从 **8% 升至 64%**，均分从 **0.094 升至 0.196**。

**增量与边界。** 它将“RSI”约束为可复跑的算法设计问题，并公开任务、评测器和全部得分提交，优于只看最终分数的 Agent demo。局限是 10 个冻结仓库与单卡、4 小时编辑预算仍是窄代理；算法创新可能被环境、启动成本或隐藏评测器的局部性低估。

**复现 / 工程价值。** 高。适合作为训练科研 Agent 的红队评测模板：冻结基线、从头运行、隐藏评估、保留所有失败提交。arXiv 页面声明发布 suite、evaluator 与 scored submissions，具体仓库链接仍需在代码页逐项审计。

### 2. MidTool：把 Agent 工具能力放到 mid-training 塑形

**论文 / 日期：** [MidTool: Mid-training Data Synthesis for Agentic Tool Use](https://arxiv.org/abs/2608.20314)，2026-08-20 提交。

**问题与机制。** 现有工作多通过 SFT/RL 的后训练教模型 function calling，作者主张通用工具使用同样需要专门的 mid-training。MidTool 从网页、PDF、代码和真实 API、MCP Skill、文档落地工作流构建开放语料，训练模型识别工具可供性、基于上下文绑定参数、组合调用流程以及在信息不全时恢复。

**关键结果（作者主张）。** Qwen3-4B-Base 与 8B-Base 先在 MidTool-Mix 上 mid-train、再做 SFT 与 RL；相对基线，在 BFCL、tau2-Bench、MCP Universe 三类评测上均有提升。论文摘要未给出逐项绝对数值，不能据此判断增益规模或成本收益。

**增量与边界。** 关键观点是将工具使用从“对齐层格式”提升为基础能力。风险在于合成监督是否过拟合 API 描述风格，MCP 工具版本变化是否造成时效衰减，以及训练语料中的真实工作流许可与泄漏边界。

**复现 / 工程价值。** 中高。arXiv 条目提供数据与模型入口；适合需要稳定 tool grounding 的开源底座，但应先检查数据来源、去重策略和工具 schema 覆盖。

### 3. Optimal Skill Selection：给 context window 内的 Skill 组合一个质量保证

**论文 / 日期：** [Optimal Skill Selection for LLM Agents with Provable Bicriteria Guarantees](https://arxiv.org/abs/2608.19993)，2026-08-20 提交。

**问题与机制。** Agent 将可复用 Skill 文档装入有限上下文时，常按独立语义相关性 top-k 或贪心拼接；这忽略 Skill 间冗余、互补与 token 成本。作者把集合选择建模为“单调子模收益 − context penalty”，提出 Best Prefix Selection（BPS），并给出 $(1-1/e,1)$ 的双准则近似保证。

**关键结果（作者主张）。** 在做过污染控制的 BigCodeBench 变体上，BPS 任务成功率 **0.73**，对比已发布 Skill router、文本检索器和执行器自选的 **0.20—0.52**，并比最强已发布 router 少用 **28% token**。

**增量与边界。** 价值在于从“召回相关文档”转到“为执行结果选择互补的上下文集合”。但子模假设、Skill 质量估计和 benchmark 的封闭 Skill 池是核心前提；真实系统中动态权限、版本冲突、多 Skill 交互和模型自身的上下文位置偏好都可能破坏保证。

**复现 / 工程价值。** 中高。对于昂贵的长 context Agent，可先离线估计 Skill 的边际收益、再做预算约束选择；arXiv 页面未列明确代码链接，当前仅能核验摘要级结果。

### 4. Phantom Gains：自训练“新学会了哪些题”也需要零假设

**论文 / 日期：** [Phantom Gains: Auditing Self-Improvement Against a Measured Null](https://arxiv.org/abs/2608.20290)，2026-08-20 提交。

**问题与机制。** 当研究者按题目追踪模型从“不会→会”或“会→不会”，本质是在相减两个有噪声的估计。作者以 Qwen3-8B 的三轮 rank-32 LoRA self-training 为例，设置经过同一管线的冻结对照，审计单次贪心解码、批处理、阈值与多重检验等七类测量失败；改用基于 pooled baseline、带 FDR 控制的逐题精确检验。

**关键结果（作者主张）。** 没有对照时，一个未训练模型也会被制造出能力变化，错误的 expansion 统计可给出 **0.280**；修正检验在所有 held-out replicate 上未发现显著逐题获得。外部蒸馏能改善基座很少解决的问题，而三种 self-training 则未显示同样证据，且会以高于测量底噪的速率破坏原本已解问题。

**增量与边界。** 与 8 月 20 日关于任务顺序脆弱性的研究相互印证：自改进不能只看均值或一条曲线，必须测量自己的 null。该结论针对特定 LoRA、模型和评测设计，不等于所有自训练无效。

**复现 / 工程价值。** 高。arXiv 条目提供代码与评估产物；任何多臂后训练项目都可将“冻结模型的同管线重复”设为最低审计门槛。
