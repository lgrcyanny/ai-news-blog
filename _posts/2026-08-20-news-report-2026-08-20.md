## 今日结论

1. **Agent 强化学习的瓶颈正在下沉到 harness（运行时外壳）层。** Agent Lightning 与 LEGO-RL 同日给出相互印证的路线：训练器不应强行接管真实 Agent 的工具循环，而应可靠捕获其原始交互、处理压缩与重序列化、隔离沙箱故障，再计算策略梯度。
2. **“自改进 Agent”需要从单次漂亮曲线退回统计学。** 新研究发现，记忆型自改进方法会放大运行噪声，且收益高度依赖任务顺序；没有多随机种子与顺序置换，所谓持续进步可能只是隐含课程学习。
3. **通用 Agent 离端到端商业交付仍远。** StartupBench 以市场验证过的创业产品工作流构造任务，最强模型成功率仍约 30%；这比单步工具调用榜单更接近真实采购风险。
4. **商业发布面今天很安静。** 已检查的主要官方源未发现足以改变能力、成本或开发范式的新增公告，不用为凑数收录活动宣传和二手转述。

## 研究前沿

### 1. Agent Lightning v1.0：把 Agentic RL 从“定制脚本”变成可复用训练基础设施

**论文 / 日期：** [Agent Lightning v1.0: Towards Harnessed Agentic RL](https://arxiv.org/abs/2608.17528)，2026-08-18 提交。

**问题与机制。** 真实编码、搜索或指令 Agent 往往自带工具、上下文压缩和控制循环，传统 RL 框架却假设训练器掌控 rollout，二者耦合后很难迁移。作者把部署时 harness 保留为交互主体，训练器只消费 LLM 请求—响应序列，并显式处理重新分词、样本合并、优势估计和后端差异。

**关键结果（作者主张）。** 约 3,500 行核心框架可接入不同 harness；使用 6,000 个样本和作者所称“适度算力”，Qwen3.5-9B 在 SWE-bench Verified 从 **41.8% 提升到 56.4%（+14.6 个百分点）**。论文还报告了指令、搜索与编码 Agent，并称公开完整编码 Agent RL 工作流和脚本。

**增量与边界。** 价值不在提出新策略梯度公式，而在把训练协议与 Agent 产品运行时解耦。当前最强证据仍集中在团队自己的流水线；跨 harness 的同模型、同数据、同预算比较，以及 6,000 样本的成本拆解仍需复核。

**复现 / 工程价值。** 高。适合已有复杂 Agent、又不愿重写运行时的团队；论文声称已发布框架与脚本，但本次未从检索结果稳定核验到独立代码仓库入口，采用前应检查许可证、提交活跃度与环境复现说明。

### 2. LEGO-RL：直接在 OpenHands、Claude Code、OpenCode 等原生 harness 中训练

**论文 / 日期：** [LEGO-RL: Harness-Native Reinforcement Learning for Coding Agents](https://arxiv.org/abs/2608.17393)，2026-08-18 提交；[项目页](https://lego-rl.pages.dev/)。

**问题与机制。** 编码 Agent 的真实轨迹会经历上下文压缩、消息重排、工具异常甚至奖励投机，直接拿最终文本训练会造成 train–inference 不一致。LEGO-RL 用进程内 LLM proxy 捕获原始流，再由训练器重算 log-prob；同时用带镜像缓存与分阶段防护的沙箱编排降低 rollout 故障，并提供实时监控界面。

**关键结果（作者主张）。** 对 Qwen3.5-35B-A3B 使用 GSPO 后，SWE-bench Verified 分别由 **OpenHands 64.0→70.4、Claude Code 62.4→68.2、OpenCode 57.2→66.6**；作者报告 rollout 与训练侧概率相关系数 **>0.99**。

**增量与边界。** 相比只支持固定 Agent 框架的训练栈，它证明同一底座可以跨三种真实 harness 优化。不过三个结果并非同一 harness 上的统一基线，不能据此比较 harness 优劣；SWE-bench 的污染控制、重复运行方差和训练成本仍需阅读全文及代码验证。

**复现 / 工程价值。** 高，尤其适合维护多种编码 Agent 前端的团队。项目页可访问；正式投入前应重点审计沙箱安全、轨迹隐私和对 harness 版本的耦合。

### 3. 自改进 Agent 的脆弱性：任务顺序可能伪装成能力增长

**论文 / 日期：** [On the Fragility of Self-Improving Agents: Variance, Task Order, and Underspecification](https://arxiv.org/abs/2608.18066)，2026-08-18 提交。

**问题与机制。** 论文重新评估两类基于记忆的自改进方法，不只跑一条任务序列，而是增加多次运行与任务顺序打乱，检验“把过去经验写入记忆”是否稳定提升未来任务。

**主要发现（作者主张）。** 自改进会放大底层 Agent 的随机性，性能增益对任务排列高度敏感，形成未声明的“隐含课程”。更细的评分规则和环境反馈能部分缩小退化，但不能消除不同顺序间差距。

**增量与边界。** 这不是更强的新方法，而是重要的测量纠偏：自改进论文至少应报告多随机种子、顺序置换、均值与方差，并将在线记忆增益与普通 few-shot / 检索基线分开。结论目前只覆盖两种记忆型方法，不能外推到参数更新、工具进化或开放式学习的全部路线。

**复现 / 工程价值。** 高于一般 benchmark 微调论文：任何持续学习 Agent 的上线评审都可直接复用其评估思想。arXiv 页面提供代码与数据外链；本日报只核验到论文页级别，尚未逐项审计复现脚本。

### 4. StartupBench：把 Agent 评测拉回可交付的商业工作流

**论文 / 日期：** [StartupBench: Benchmarking General-Purpose Agents on Market-Validated End-to-End Workflows](https://arxiv.org/abs/2608.17800)，2026-08-18 提交。

**问题与机制。** 许多 Agent benchmark 是人工拼装的短任务，难以回答“能否替代一个真实 SaaS 工作流”。StartupBench 从已有用户采用信号的 AI 创业产品抽取端到端任务，以最终交付物和细粒度 rubric 评分，覆盖复杂指令遵循与领域知识。

**关键结果（作者主张）。** 最强被测模型成功率仍只有 **约 30%**；主要失败来自长程指令遵循和领域专业性，而非单纯不会调用工具。

**增量与边界。** “市场验证过的工作流”比浏览器点击数更接近采购价值，但也可能偏向公开、易演示且可自动评分的创业产品；产品采用度如何量化、人工 rubric 一致性及任务泄漏都决定可信度。当前 arXiv 条目未见明确代码 / 数据入口。

**复现 / 工程价值。** 中高。适合作为企业 Agent 验收清单的设计参考，不宜把 30% 直接解释为所有知识工作自动化率。
