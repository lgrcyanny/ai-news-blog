## 今日结论

1. **Agent 的上下文压缩不能只看任务成功率。**一项受控实验中，GPT-5.5 在 5× 压缩下完成率从 80% 到 85%、统计上无差异，但检索调用从 21.0 增至 63.9。被压掉的执行状态会以工具重查、延迟和外部 API 成本的形式回来。
2. **并行推理开始从固定采样转向动态算力调度。**ParaTempo 以分支答案分布随时间的收敛程度为统一控制信号，作者报告在保持竞争性准确率时减少 21.8%–32.2% 延迟和 18.1%–30.3% token；代码已公开，但仓库刚建立、尚无社区验证。
3. **多 Agent 讨论并不天然带来“群体智慧”。**Stanford 团队在逾 10,000 个语言模型 Agent 群体上观察到冷漠、极化和共识三类宏观状态；客观题交流平均改善正确性，主观政治题却可能放大方向性偏差。Agent 拓扑和互信关系应成为系统参数，而不是随意的 prompt 编排。
4. **IJCAI-ECAI 2026 已进入主技术日程。**大会 8 月 18–21 日在 Bremen 举行，今天安排 David Parkes 的 John McCarthy Award 演讲与 Industry Day；当前未核验到新公布的 best paper 名单。

## 研究前沿

### 1. [上下文压缩会给 Agent 带来什么隐藏成本？](https://arxiv.org/abs/2608.16370)（提交于 2026-08-17）

**问题与方法。**常见评测只看任务是否完成，却遗漏 Agent 为找回被压缩信息而增加的交互。论文在固定 24 轮的确定性规划环境中比较直接丢弃与事实保留型压缩，将工具调用拆成检索和执行，并用受控 oracle 恢复缺失状态；覆盖 3 个模型、2 类任务。

**关键结果（作者主张）。**六个“模型×任务”组合的检索调用全部增加，Holm 校正后五个仍显著。预注册的 5× 压缩点上，所有组合完成率变化均不显著；GPT-5.5 完成率 80%→85%（p=1.0），检索调用却由 21.0→63.9（p=.002）。把保留状态替换为语义无关内容，检索增加 57%（p<.001），完成率仍无显著变化；但在 ALFWorld 中未出现同样的检索激增。

**增量、边界与价值。**增量是把“状态重获成本”单列为可测指标，说明 context engineering 应同时报告成功率、外部调用、延迟和重试。边界也很重要：主实验是有 oracle、有限步长的受控环境，ALFWorld 的反例表明结果依赖任务结构；条目未提供代码链接。**分析**：生产 Agent 应记录压缩前后“每个成功任务的检索次数/工具费用”，并优先保留执行依赖、权限和未完成承诺，而非只做语义摘要。

### 2. [ParaTempo：用时间置信度调度并行推理](https://arxiv.org/abs/2608.16425)（提交于 2026-08-17）

**机制。**框架定期探测每条推理分支的暂定答案分布，用近期探测是否持续集中于同一答案定义“时间置信度”。低置信分支被剪枝，持续稳定分支提前退休，释放出的预算用于复制更有希望的分支；加权投票足够集中时全局停止。它无需训练，也无需等待全部分支同步。

**结果（作者主张）。**数学与科学推理基准上，平均延迟降低 21.8%–32.2%，token 降低 18.1%–30.3%，准确率保持竞争力。官方[代码仓库](https://github.com/ScottZhang812/ParaTempo)支持 AIME26、HMMT25/26、GPQA，默认 16 分支、每 500 token 探测一次，可接 Qwen3.5-35B-A3B 与 GPT-OSS-20B 的本地 vLLM 端点。

**边界与价值。**探测本身消耗推理，且“答案趋稳”不等于“答案正确”；开放式写作、代码修改等没有紧凑答案空间的任务未证明适用。仓库 8 月 17 日才发布，仅 4 次提交、无 release，成熟度很低。**分析**：它最适合答案可规范化、可多数投票的高成本推理；工程验证应报告 P95 延迟、探测开销和错误一致收敛率，而非只看平均 token。

### 3. [Physics of Agents：用统计力学预测多 Agent 群体行为](https://arxiv.org/abs/2608.16578)（提交于 2026-08-17）

**问题与机制。**作者让不同 persona 的 Agent 在带正/负关系的通信图上反复交换消息、更新二元意见，并将更新映射到带内在偏置与邻居作用力的 Ising/Glauber 型模型。完整数据包括逾 10,000 个群体；主分析为 4 个模型、60 个客观/主观问题、不同图结构与重复采样形成的 9,600 个群体，每群通常 32 个 Agent、8 轮交互。

**结果（作者主张）。**群体宏观上落入冷漠、极化、共识三种状态，互动通常提高确信度；客观数学题中交流平均推动正确答案，主观政治题则可能出现向右漂移。拟合模型仅凭初始意见即可预测个体轨迹，优于论文所列基线并泛化到未见图结构。代码、数据和在线附录已公开在[官方仓库](https://github.com/batu-el/physics-of-agents)，Apache-2.0 许可。

**增量、边界与价值。**价值在于把群体行为从“多跑几个 Agent 看结果”转成可拟合动力学，并提示友好/对抗边、连接拓扑会改变结论。实验意见被离散成二元状态，角色和关系由提示词构造，不能直接外推到拥有长期记忆、工具和真实利益冲突的 Agent 市场。**分析**：多 Agent 系统评测应加入观点多样性、错误相关性、极化与多数翻转率；让所有 Agent 互相赞同，可能只是更快形成共识，不是更接近真相。

### 4. [TRCA：从状态转移而非成功轨迹分配长程 Agent 奖励](https://arxiv.org/abs/2608.16156)（提交于 2026-08-17）

**机制。**长程 Agent 早期成功轨迹稀少，终局奖励难定位哪一步有效。TRCA 不训练额外过程奖励模型，而按 Evidence（获得任务相关信息）、Execution（有效执行）和 Invalidity（无效/退步）三类 rubric 评估每次动作造成的状态转移；基础奖励衡量局部质量，突破奖励只奖励新覆盖的证据与执行条件，再与终局结果联合优化。

**结果（作者主张）。**在 ALFWorld、WebShop 和 7 个 SearchQA 基准上均优于作者所选基线；Qwen2.5-7B-Instruct 的 WebShop 分数提高 6.0%–12.6%，Qwen2.5-3B-Instruct 的 SearchQA 平均分提高 1.9%–18.3%。

**边界与价值。**它绕开“必须先有成功轨迹”的冷启动问题，但 rubric 判断仍可能贵、偏或被策略钻空子；arXiv 条目未附代码，无法立即核验训练细节。**分析**：对浏览器/运维 Agent，最可迁移的是“新证据覆盖”和“有效状态变化”两个奖励维度；部署前必须检查奖励模型是否把重复查询或表面动作误判为进展。
