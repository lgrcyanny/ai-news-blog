## 📚 学术研究

### 🌟 重点论文解读

#### 1. Rethinking RL for LLM Reasoning: It's Sparse Policy Selection, Not Capability Learning
- **arXiv**: [2605.06241](https://arxiv.org/abs/2605.06241)
- **核心贡献**: 通过跨模型家族和 RL 算法的 token 级分析，提出一个颠覆性观点——**RL 并未教会模型新的推理策略，只是将概率质量重新分配到基座模型已经包含的解法上**
- **关键发现**:
  - RL 的有益影响在策略初始化阶段（前几步）就已完成
  - 进一步的 RL 优化只是对已有解法的概率重新加权
  - RL 的"学习"本质上是**稀疏策略选择（sparse policy selection）**而非能力增长
- **专业解读**: 这篇论文对当前火热的 RLVR（Reinforcement Learning with Verifiable Rewards）范式提出了根本性质疑。如果 RL 只是在已有能力空间内做概率重分配，那么：
  1. **RL 的价值边界**：RL 不是"教"模型推理，而是"选"出模型已有的好推理路径。这意味着基座模型的预训练质量比 RL 训练更重要
  2. **训练效率**：如果 RL 的早期步骤就完成大部分工作，那么大规模 RL 迭代可能是浪费计算资源
  3. **方法论启示**：与其投入大量资源做 RL fine-tuning，不如优化基座模型的预训练，使其在 pre-training 阶段就内化更多高质量推理路径
  这是一个值得整个社区重新审视的结论。如果得到广泛验证，可能会改变从 DeepSeek R1 到 OpenAI o 系列等所有基于 RL 推理增强模型的训练策略。

#### 2. AEM: Adaptive Entropy Modulation for Multi-Turn Agentic Reinforcement Learning
- **arXiv**: [2605.00425](https://arxiv.org/abs/2605.00425)
- **核心贡献**: 提出**自适应熵调制（Adaptive Entropy Modulation）**，仅用稀疏的结果奖励即可实现有效的多轮 agentic RL，无需过程奖励模型或辅助自监督信号
- **方法要点**:
  - 根据任务进展动态调节 agent 的探索/利用熵
  - 在不确定状态增加熵（鼓励探索），在确定状态降低熵（鼓励利用）
  - 通过熵调制隐式实现步骤级信用分配
- **专业解读**: 多轮 agentic RL 的核心难题是信用分配——当最终奖励到达时，如何知道轨迹中的哪些步骤是好/坏的？现有方法（如过程奖励模型、self-rewarding）增加了大量训练复杂度和计算成本。AEM 的巧妙之处在于：**不需要告诉 agent 哪一步是对的，而是通过调节 agent 的"信心水平"来引导其行为**。在任务早期（不确定性高），增加熵让 agent 多尝试；在任务后期（接近完成），降低熵让 agent 收敛。这种"元级别"的引导比直接给步骤奖励更优雅、更通用。对于构建 real-world agent 系统，这是一个非常有实用价值的方法。

#### 3. LLMs Improving LLMs: Agentic Discovery for Test-Time Scaling (AutoTTS)
- **arXiv**: [2605.08083](https://arxiv.org/abs/2605.08083)
- **核心贡献**: 提出 **AutoTTS**，一个环境驱动的框架，用 LLM agent 自动发现 test-time scaling（TTS）策略，取代手工设计的推理模式
- **方法要点**:
  - 将 TTS 策略发现转化为 agent 在环境中的搜索问题
  - agent 通过 trial-and-error 探索最优的推理步骤组合和资源分配策略
  - 自动发现人类研究者可能忽略的高效计算分配方案
- **专业解读**: Test-time scaling 是当前提升 LLM 推理能力最热门的方向之一（从 OpenAI o1 的 chain-of-thought 到 Google 的 adaptive computation）。但现有 TTS 策略几乎全部是手工设计的——研究者凭直觉设计推理模式并调参。AutoTTS 将这一过程自动化：用 LLM agent 自己来发现"如何更好地思考"。这标志着 TTS 从"手工工程"向"自动发现"的范式转移。更重要的是，这种 agentic discovery 的框架可以推广到其他超参数搜索和架构搜索问题。

#### 4. HyperEyes: Dual-Grained Efficiency-Aware RL for Parallel Multimodal Search Agents
- **arXiv**: [2605.07177](https://arxiv.org/abs/2605.07177)
- **核心贡献**: 提出**并行多模态搜索 agent**，将视觉 grounding 和检索融合为单个原子动作，通过 RL 训练实现"搜索更宽而非更长"的策略
- **关键创新**:
  - 将多个独立子检索请求并行化，而非串行处理
  - 双粒度效率感知 RL：同时优化搜索质量和计算效率
- **专业解读**: 当前的多模态 agent 在处理需要多实体检索的查询时，通常是串行的——逐个处理每个实体，每个实体发一个 tool call。HyperEyes 的核心洞见是：**当查询可以分解为独立子任务时，并行搜索比串行搜索效率更高**。这类似于人类的搜索策略——当需要了解多个独立事实时，我们会同时打开多个浏览器标签页，而非一个一个查。通过 RL 训练 agent 学会判断何时并行、何时串行，这是一个实用且直观的设计。

#### 5. PrefixGuard: From LLM-Agent Traces to Online Failure-Warning Monitors
- **arXiv**: [2605.06455](https://arxiv.org/abs/2605.06455)
- **核心贡献**: 提出从 LLM agent 执行轨迹自动生成**在线故障预警监控器**的框架，无需人工编写事件模式或使用昂贵的运行时 LLM 评判
- **方法要点**:
  - 离线阶段：从 agent 轨迹中自动归纳确定性的类型化步骤适配器（StepView）
  - 训练轻量级监控器模型，在 agent 执行过程中实时检测潜在故障
  - 支持在最终结果检查之前就进行干预
- **专业解读**: 随着 LLM agent 被部署到生产环境中处理长程、高风险任务，安全监控成为刚需。现有方法要么依赖人工编写的规则（brittle），要么依赖运行时 LLM 评判（costly）。PrefixGuard 的思路很巧妙：**从历史轨迹中自动学习"正常模式"，然后实时监控偏离**。这类似于工业控制系统的异常检测——不需要预先知道所有可能的故障模式，只需要知道"正常"长什么样。对于生产级 agent 系统，这是一个非常实用的安全基础设施。
