## 📚 学术研究

### 🌟 重点论文与博客解读

#### 1. EMO: Pretraining Mixture of Experts for Emergent Modularity
- **来源**: HuggingFace Blog (Allen AI, 2026-05-08)
- **核心贡献**: 在 MoE 预训练阶段引入结构性约束，使得专家的专业化（模块化）**自然地涌现**，而非事后设计
- **关键方法**: 通过负载均衡损失、专家容量限制和路由正则化，在预训练过程中引导不同专家自发分化为语法专家、知识专家、推理专家等
- **专业解读**: 传统 MoE 的专家分工通常是训练后通过探测发现的，EMO 把「涌现模块化」前移到了预训练阶段。如果专家分工是可预测的，MoE 模型的可解释性和可控性将大幅提升——你可以精确知道哪个专家在处理数学推理、哪个在负责代码生成。这对 MoE 架构的 debug 和优化有直接工程价值

#### 2. Granite Embedding Multilingual R2: Apache 2.0 开源多语言嵌入模型
- **来源**: HuggingFace Blog (IBM, 2026-05-14)
- **核心贡献**: 支持 32K 上下文窗口的多语言嵌入模型，Apache 2.0 许可，在 <100M 参数规模上达到 SOTA 检索质量
- **关键指标**: Sub-100M 最佳检索质量，支持 12+ 语言，32K token 上下文
- **专业解读**: 32K 上下文对于嵌入模型来说是**实用化的关键门槛**——长文档（法律合同、学术论文、代码库）不再需要分块后分别嵌入。Apache 2.0 许可意味着真正的商业友好。IBM 在开源嵌入赛道的投入值得关注，可能改变当前以 OpenAI/Mistral 嵌入为主的格局

#### 3. Unlocking Asynchronicity in Continuous Batching
- **来源**: HuggingFace Blog (2026-05-14)
- **核心贡献**: 提出在 continuous batching 中引入异步处理机制，突破同步 batch 的 GPU 利用率瓶颈
- **专业解读**: Continuous batching 是 vLLM 等推理引擎的核心技术，但当前实现中 batch 内的所有请求需同步等待。异步 continuous batching 可以让完成的请求提前返回、新请求即时加入，进一步榨取 GPU 利用率。这对于高并发 LLM 服务场景（如 API 服务）的吞吐量提升有直接意义，与昨日 DFlash 的推理加速形成互补——一个优化单请求延迟，一个优化系统吞吐

#### 4. vLLM V0 to V1: Correctness Before Corrections in RL
- **来源**: HuggingFace Blog (ServiceNow AI, 2026-05-06)
- **核心贡献**: 探讨 vLLM 从 V0 到 V1 架构升级中「正确性优先于修正」的设计哲学，特别是在 RL（强化学习）场景下的推理正确性保障
- **专业解读**: 「先保证正确、再追求速度」——这与当前 AI 推理加速领域「先压延迟再修 bug」的主流做法形成对比。在 RL 场景下，推理错误会在训练过程中被放大，因为错误的 action/value 估计会直接污染训练信号

- Codex（可写代码、操作文件的桌面 AI agent）现在可以通过 ChatGPT 手机 App 访问
