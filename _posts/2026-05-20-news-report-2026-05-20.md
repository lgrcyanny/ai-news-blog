### 重点论文解读

#### 1. CHI-Bench: Can AI Agents Automate End-to-End, Long-Horizon, Policy-Rich Healthcare Workflows?

- **来源**: arxiv.org/abs/2605.16679
- **核心贡献**: 首个面向真实医疗工作流的 Agent 基准——不是简单的 QA 或诊断，而是要求 Agent 完成「端到端、长周期、策略密集」的医疗流程（如保险预授权、多科室转诊协调）
- **方法**: 构建了覆盖 12 个真实医疗场景的测试集，每个场景涉及 15-40 个步骤、多系统交互（EHR、保险、药房）、策略约束（HIPAA 合规、临床指南）。评估了 GPT-4、Claude、Gemini 等 Agent 的表现
- **价值**: 如果 Agent 能通过 CHI-Bench，意味着 AI 可以从「医疗辅助」进入「医疗流程自动化」。这对 Agent 的工具使用、长期记忆、策略遵循能力提出了极限挑战——医疗是容错率最低的领域之一

#### 2. AstraFlow: Dataflow-Oriented Reinforcement Learning for Agentic LLMs

- **来源**: arxiv.org/abs/2605.15565
- **核心贡献**: 重新定义 Agent 工具调用的 RL 训练范式——从「步骤序列」转向「数据流图」，Agent 学会按数据的生产-消费关系编排工具调用
- **方法**: 将 Agent 的工具调用链建模为有向无环图（DAG），RL 训练时 reward 基于数据流图的效率和正确性，而非步骤顺序。Agent 学习识别哪些工具调用可以并行（数据无关），哪些必须串行（数据依赖）
- **价值**: 这是 Agent 编排效率的关键突破。当前 Agent 倾向于线性执行工具（调用 A → 等结果 → 调用 B），但很多工具调用可以并行。Dataflow-aware 的 Agent 可以在复杂任务中大幅缩短执行时间

#### 3. Post-Trained MoE Can Skip Half Experts via Self-Distillation

- **来源**: arxiv.org/abs/2605.18643
- **核心贡献**: 发现后训练的 MoE 模型存在大量冗余专家——通过自蒸馏训练学生模型（跳过一半专家），推理速度翻倍且性能无损
- **方法**: 在已训练好的 MoE 模型上，分析专家激活模式，识别出可被跳过的「惰性专家」。用原始模型作为教师，训练一个专家减半的学生模型，通过自蒸馏保持输出质量
- **价值**: 对 MoE 推理部署的直接实用价值——DeepSeek-V3、Mixtral 等 MoE 模型的推理成本可以大幅降低。更重要的是，这暗示 MoE 训练可能不需要那么多专家，未来 MoE 架构设计可以考虑「先训练多专家再蒸馏压缩」的策略

## 💡 今日洞察

1. **Agent 数据流编排是下一个效率瓶颈** — AstraFlow 和本周的多篇 Agent RL 论文共同指向一个问题：当前 Agent 的工具调用是线性、顺序的，而现实任务有天然的并行性。从「步骤序列」到「数据流图」的范式转换，可以让 Agent 在复杂任务中的执行时间缩短数倍。这与昨天 Nudging Beyond Comfort Zone 的「探索效率」形成互补——前者解决 Agent 如何「编排得更聪明」，后者解决 Agent 如何「敢于尝试新组合」

2. **MoE 模型的「专家冗余」正在被系统性揭示** — Post-Trained MoE Can Skip Half Experts 不是孤例。本周还有 SlimQwen（MoE 剪枝+蒸馏）、UniSD（统一自蒸馏框架）等论文从不同角度证明：MoE 训练后存在大量可压缩空间。如果这一趋势持续，MoE 架构的设计理念可能从「训练时多用专家→推理时全保留」转向「训练时多用专家→推理时压缩到极限」
